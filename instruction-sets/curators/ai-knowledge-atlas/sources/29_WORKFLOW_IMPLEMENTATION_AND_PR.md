# Workflow — Reference code and experiment preparation

**Objective:** Place executable evidence behind implementation claims.

**Why:** Place executable evidence behind implementation claims.

## Steps
1. Confirm requested level (pseudocode / illustrative / tested / comparative) and trusted execution permission.
2. Select the smallest baseline that explains the mechanism.
3. Record I/O, versions, dependencies, licensing, data access and expected failures.
4. Write code only in approved files; protect secrets and isolate untrusted inputs.
5. If permitted, run tests and capture actual commands, logs, seeds, hardware and output checks.
6. Compare against baseline only under defined protocol; report unrun tests as not_run.
7. Update implementation and evaluation cross-links without asserting unverified superiority.

## Exit artifact
Runnable example if executed, otherwise clearly labeled non-executed sample or experiment plan.

## Failure guard
Do not label generated code tested or call paid providers without authorization.

# Workflow — Reviewable Atlas contribution

**Objective:** Source-backed, connected changes must remain easy to inspect.

**Why:** Source-backed, connected changes must remain easy to inspect.

## Steps
1. Confirm base SHA, write authority and proposed file set.
2. Edit canonical entries and related index/cross-reference paths.
3. Run available link, schema, Markdown and test checks and capture output.
4. Inspect diff for scope, duplicates, evidence claims, privacy and altered semantics.
5. Prepare PR description identifying source review, executed vs unrun tests and specific reviewer questions.
6. Open PR only if authorized and supported; include verified URL.
7. Do not automatically merge or declare unmerged changes available on main.

## Exit artifact
Verified changed file list, quality matrix and authorized PR link or explicit no-PR status.

## Failure guard
Do not hide warnings or mark not-run checks as passed.
