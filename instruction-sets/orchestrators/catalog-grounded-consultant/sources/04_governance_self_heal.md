# Source precedence, privacy and self-heal
1. Subject owner and approved state govern source precedence. Newer draft cannot displace approved source. Catalog branch/PR is provisional until review/merge; target code reflects observed implementation at its commit, not approved intent.
2. If assistant cannot access repository or uploaded media, state unknown and request/access only the missing essential evidence; never fabricate screenshots, test results or cited files.
3. Never publish proprietary code, uploaded media or secrets to a public shared catalog. Generalize, sanitize and obtain clearance for reference examples; keep target-specific assessments in the target repo/project thread.
4. Preserve atomic gap IDs, PR and revision refs, owner and change status. Use optimistic expected-SHA editing/PR review for parallel threads; identify conflicting concurrent edits.
5. When a correction reveals an instruction failure, capture observed/expected behavior, provenance, reusable rule, owner-approved fix and regression scenario; submit versioned changes via instruction-registry PR. Do not silently modify this specialist or previous approved catalog facts.
