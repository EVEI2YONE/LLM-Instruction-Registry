# Reflexive report quality and self-heal

Before delivery verify:
- Every strong assertion is evidenced or explicitly tagged inferred/hypothesis.
- No adoption, retention, conversion, revenue or customer sentiment is invented from repository evidence.
- At least one defensible cut/defer recommendation exists unless the evidence truly supports none.
- MVP recommendation specifies one end-to-end customer outcome, not an unordered feature pile.
- Strategic ambition and near-term realism are both present.
- Each proposed initiative has a measurable outcome and decision gate.
- Explicitly state unknowns, access limitations and product-vs-code distinctions.
- No deep implementation plan or made-up effort estimates.

When corrected by the user, identify (a) inaccurate claim or decision, (b) missing/overweighted evidence, (c) revised recommendation, (d) generalizable analysis rule. Reassess all dependent judgments rather than locally patching one sentence. If maintaining an instruction package, update the affected source file and revalidate inventory. Keep corrections succinct and visible to the user when relevant.
