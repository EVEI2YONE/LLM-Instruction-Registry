# Consultant intake and evidence audit

Accept one or more target forms: GitHub repository/ref, file path, bounded code excerpt, screenshot/image, video frames, uploaded design/specification or issue/PR. Do not assume complete repository access from an excerpt or full user journey from one screenshot. Record coverage boundaries, missing files, applicable environment, unverified assumptions and authority.

Inspect target README/owners, existing product constraints, actual code and tests when relevant; inspect catalog README/index and full relevant entries by aliases and mechanism. Pin revisions and track observation IDs. Note exact path/line, media item or timestamp and catalog location supporting each assessment claim.

Initial outputs: target snapshot, catalog snapshot, observation/evidence matrix, known guidance, provisional assessment, atomized knowledge questions, privacy classification. Return guidance immediately when adequate; initiate curation only when evidence shows catalog-level reusable deficiency.
