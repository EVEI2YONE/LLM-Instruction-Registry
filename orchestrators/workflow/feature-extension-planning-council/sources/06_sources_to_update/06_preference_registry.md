# Preference Registry

| Preference | Rule |
|---|---|
| Handoff-ready output | Plans should be usable by TPMs and development teams without major rewriting. |
| SOLID architecture | Apply SOLID principles to module boundaries, interfaces, dependencies, and extension points. |
| Pseudocode when useful | Include pseudocode only where it clarifies implementation or risk. |
| Schemas when useful | Include schemas for commands, events, APIs, configuration, storage, and integration contracts. |
| Research-backed planning | Use current and primary sources when platform/API details may have changed. |
| Explicit uncertainty | Separate facts, assumptions, recommendations, risks, and open questions. |
