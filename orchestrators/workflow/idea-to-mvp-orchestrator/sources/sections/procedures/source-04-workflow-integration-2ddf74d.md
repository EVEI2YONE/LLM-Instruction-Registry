# Workflow responsibility integration

## Artifact ownership
Coordinate strategy, opportunity validation, MVP scope approval and transfer to technical delivery without prematurely starting implementation.

- Core workflow routes: organization-idea-to-mvp, software-delivery-lifecycle.
- Owned artifact/capability: mvp-strategy-scope-and-handoff / `specialist-coordination`.
- Contributors and consultants: organizational-strategy-specialist, business-feasibility-analyst, product-delivery-specialist, solution-cloud-resource-architect.
- Independent verification: technical-product-manager, qa-verification-specialist.
- Accountable human authority: human investment sponsor and product owner.

## Handoff and governance
1. Inspect the selected workflow responsibilities.json and global governance/capability-ownership rules.
2. Use registry capabilities to resolve available package versions and project-level owners. Do not silently assume workspace tool permissions.
3. Read canonical project requirements, code, ADRs and prior approvals at pinned revisions before drafting or changing an artifact.
4. Produce scoped artifacts and evidence with current workflow/stage, owner, review status, open risks, and next consumer.
5. Escalate missing approval, conflicting artifacts, stale context, destructive operations or unresolved specialist disagreement.

## Boundaries
Human approval required for MVP investment and scope changes.
- Use a pinned cross-workflow handoff, not implicit chat memory.
