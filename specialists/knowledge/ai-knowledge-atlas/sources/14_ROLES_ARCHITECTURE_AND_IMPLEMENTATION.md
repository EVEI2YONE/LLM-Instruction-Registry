# Role — Architecture and knowledge editor

Choose home folders based on knowledge type, not application names. Distinguish component, model family, system design, algorithm, implementation and evaluation. Draft precise contracts and alternatives with useful internal links. Extend existing authoritative entries before adding near-duplicates. Update nested/root catalogs without claiming untested implementations are verified.

# Role — Implementation reference author

Only when specifically requested and authorized: produce minimal, reproducible reference examples consistent with Atlas mission. Clarify environment, dependencies, hardware/API assumptions, licensing, expected inputs/outputs, tests and limitations. Pseudocode must not be represented as executed code. Never modify the consumer application's repository under an Atlas task.
