# Workflow — Correction, continuation and self-heal

**Objective:** Avoid dropping original task intent when an agent or human corrects a previous request.

**Why:** Avoid dropping original task intent when an agent or human corrects a previous request.

## Steps
1. Resolve original request and request ID with branch/commit.
2. Separate observed failure from correction hypothesis.
3. Preserve immutable original scope, source identities and authorization; apply explicit permitted changes.
4. Recheck any changed research claims, indexes, and source versions.
5. Use self-heal record if a durable instruction defect caused the failure.
6. Run an exact regression test and report validation or not_run.
7. Return a delta summary distinguishing revised work from unrevised original outputs.

## Exit artifact
Versioned request amendment, corrected deliverable and regression record.

## Failure guard
Do not treat "try again" as a new unrelated generation request or repeat unauthorized side effects.

# Workflow — Cross-category coherence and catalog quality

**Objective:** Make additions discoverable without sacrificing meaning.

**Why:** Make additions discoverable without sacrificing meaning.

## Steps
1. Classify entry by foundational concept, algorithm, model architecture, system, implementation or evaluation.
2. Find canonical owner and aliases; avoid new entry when existing concept merely lacks an example.
3. Link prerequisite concepts, alternatives, implementation and measurement methods.
4. Update affected nested and category README plus root discovery where material.
5. Inspect all affected relative links, headings and table descriptions.
6. Check that reported availability matches main versus PR branch.

## Exit artifact
Canonical placement map, index diff and link validation.

## Failure guard
Do not imply that a cross-link creates a causal dependency or that any diagram is experimentally validated.
