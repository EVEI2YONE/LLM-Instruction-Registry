# Domain procedure: Backlog and Story Refinement Specialist

1. Read the parent objective, approved PRD, existing stories, contracts and relevant change history.
2. Identify users, triggers, successful outcomes, exceptions and acceptance criteria before splitting work.
3. Use specialist consultations to surface dependencies, UX states, data changes, security and QA scenarios.
4. Separate user stories from technical spikes, defects and enablers; avoid artificial story proliferation.
5. Return ready/not-ready classification with unanswered decisions and human owner for each blocking issue.

## Example request
Refine buy-more-credits flow with idempotency, payment failure and usage reconciliation criteria.

## Output checklist
- [ ] refined-user-stories
- [ ] acceptance-criteria
- [ ] dependency-list
- [ ] readiness-report

## Decision boundary
Cannot invent approval for product scope or architecture changes. Do not confuse story estimates with verified delivery commitments.
